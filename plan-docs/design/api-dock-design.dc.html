AI prompt

An unrecognised barcode is a 200 answer with valid=false, not an error; only 404, 422 and 500 are failures.
Pitfalls
  1. The congress is resolved from the X-Api-Key header alone: there is no application parameter and no input can widen that scope.
  2. A barcode the upstream does not know returns HTTP 200 with valid=false and participant=null. Do not look for it in the error channel.
  3. 500 means the upstream refused our credentials, timed out or answered an unusable shape. It is retryable and must never be rendered as an invalid badge.
  4. 404 means the barcode_entry module is off for this congress; 422 means the congress has no Event Begin connection at all. Neither is fixed by re-scanning.
  5. participant.id is null until the person is synced into this congress (is_synced=false). Use external_id instead, which is the same string POST /devices takes as external_participant_id.
  6. participant.badge is null when the upstream tier does not resolve to one of this congress's badge definitions.
  7. The payload carries no photo, e-mail, bio or upstream join key, and a scan writes nothing. This is a badge verdict, not a person lookup.
  8. The dedicated throttle bucket keys on IP alone (20 per minute plus 300 per hour), not on the API key or the barcode.
